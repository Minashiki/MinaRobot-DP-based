## 运行接口

```python
from feedingrobot.sim.task import FeedingTask
from feedingrobot.sim.images import image_to_cnn, resize_area

task = FeedingTask()
task.reset(seed=42, split="debug", episode_id=1)
observation = task.observe()
result = task.step_delta([0.001, 0., 0., 0., 0., 0.])
task.close()
```

`step_delta(action)` 是动作入口，接受有限六维基座系米/弧度命令。每次调用从实测 TCP 构造 `p_target = p_actual + Δp`、`R_target = Exp(Δr) · R_actual`；旋转为左乘。目标仅应用一次，在 50 个 1 ms 物理子步内保持不变。动作没有 Python 裁剪，也没有旧 twist 的速度、加速度、参考偏差或工作区拒绝。50 ms 结束后保持最后关节参考，实际跟踪残差保存在返回值的 `control` 中。

`step_physics()` 继续推进一个子步，也用于恢复后完成尚未执行的动作。处于故障终止状态时须 reset；有剩余子步时不能提交新动作。

`render_rgb()` 返回同一物理状态的两路 256×256 HWC `uint8`。`observe()` 的白名单只有 `agentview_image`、`robot0_eye_in_hand_image`、`robot0_eef_pos`、`robot0_eef_quat`；图像为240×240 CHW `float32 [0,1]`，TCP 为实测基座系 xyz 和连续符号的 wxyz。渲染不推进物理。时序历史由后续策略层组装。

RGB 数值契约为 `256 uint8 → 精确像素面积重采样240 uint8 → /255 → 216裁剪 → 2x−1`。`image_to_cnn(resize_area(rgb256))` 从uint8执行一次/255、216裁剪和2x−1；不要把 `observe()` 的浮点图再次传入该函数。训练裁剪必须传入显式 RNG；推理默认中心裁剪。当前没有额外图像增强。

## 快照 schema 2

正式 `get_state()/set_state()` 保持完整签名检查；schema 1 或不同模型/配置的状态直接拒绝。除 P1 的物理、布局、边界、驱动、接触、随机源和诊断记忆外，schema 2 保存：

- 固定 TCP 目标、全关节参考、原动作、动作编号、执行及剩余子步、最后 IK 速度、状态和故障详情。
- 子步穿透累计时间、峰值和事件；观测四元数符号历史。
- 与控制器一致的臂部伺服参考。

恢复后只调用 `step_physics()` 执行剩余子步，不能再次提交原 delta。P3 验收在第17子步保存，切换布局后恢复并继续33子步，与未中断执行一致；墙钟耗时仅保留诊断，不要求运行后逐值相等。

## 控制与安全

Mink 核心保留非臂 DOF 冻结、关节配置约束、0.8 rad/s 可行速度约束，以及 5 mm 最小距离/20 mm 检测距离的碰撞约束。旧位置伺服和 MuJoCo 物理限界保持原值。IK 失败、非有限求解、冻结 DOF 异常或参考越界停止动作；速度、冻结 DOF 及参考边界的浮点检查均使用1e-7绝对容差，运行与恢复采用相同边界规则，求解结果不裁剪。

每个子步检查应用态与 forward 后状态：接触组对合力5 N、补偿腕力8 N、实测臂关节速度2 rad/s、数值故障，以及普通接触穿透3 mm持续5 ms、Bean穿透0.4 mm即时终止。穿透时间每子步仅累计一次。故障后停止剩余子步，保持有限的实测臂关节参考，保留原动作、原目标、触发原因和残差。

reset 与 Bean 自然沉降保持 P1 的 holding 路径和候选拒绝规则，不运行 delta IK。其 Bean 初态穿透检查仍由 P1 沉降验收执行。

## 定标、遮挡与正式冻结
